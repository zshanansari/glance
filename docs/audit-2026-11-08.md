# Glance audit, 8 November 2026

Scope: the whole repository at v0.10.0 (commit 1a58692), the upstream project
it was forked from (vipinsight/calendo), the GitHub repository settings, and
the README and other docs. Every finding below was checked against the code;
line numbers are from that commit.

## Verdict

The app is in good shape. The command surface between the webview and the
host is tight, nothing shells out, every URL the host opens is allowlisted
or built from a fixed host, the CSP has no `unsafe-inline`, each window has
its own capability, the updater is HTTPS plus a minisign key, and settings
are written atomically with owner-only permissions. All local checks pass:
typecheck, 225 TypeScript tests, 84 Rust tests, `cargo fmt`, and `clippy -D
warnings`.

There are no high-severity security findings. There are two user-visible
correctness bugs, a handful of robustness gaps, and a repository whose
settings contradict its own SECURITY.md and CONTRIBUTING.md.

## Security

Ranked. None is exploitable without a compromised webview or a crafted
calendar invite that the user then clicks Join on.

1. **Meet and Teams links pass on host alone.** `src-tauri/src/events.rs:314`
   returns true for `meet.google.com`, `teams.microsoft.com` and
   `teams.live.com` with any path, and for any non-www `webex.com`
   subdomain. A calendar invite whose notes carry a support or redirect page
   on those hosts gets a Join button and the global join chord opens it.
   Fix: require Meet's `/xxx-xxxx-xxx` or `/lookup/` path and Teams'
   `/l/meetup-join/` or `/meet/`; add negatives to
   `tests/fixtures/meeting-links.json`. Webex paths vary too much to narrow
   safely.
2. **Framed tray glyph is capped by PNG bytes, not by decoded size.**
   `lib.rs:210` keeps PNGs under 64 KiB, then `tray.rs:468` decodes with the
   image crate's default limits, and `with_update_dot` copies the whole
   buffer on the main thread every minute. A 64 KB PNG can inflate to
   hundreds of megabytes. Fix: reject anything over 64×64 after decoding.
3. **`update_settings` accepts an unbounded patch.** `hidden_calendar_ids`
   has no cap on count or length; a huge list is fsynced, re-emitted to all
   three windows, and cloned on every fetch. Fix: cap in `normalize`.
4. **`TrayMenu` is `unsafe impl Send + Sync` over `Retained<NSMenu>`**
   (`tray.rs:167`). Sound today because all use is on the main thread, but
   nothing enforces it. Store the pointer as `usize` as
   `present_status_item_menu` already does.
5. **Access prompts leak one block each** (`events.rs:685`, `:746`
   `mem::forget`). Bounded by button presses. Pass `&completion` as the
   reminders fetch does.
6. **Release bundles ship TypeScript source maps.** `copy-static.mjs`
   builds with `sourcemap: true` and `frontendDist` has no exclusion, so
   452 KB of `.js.map` with full `sourcesContent` is embedded in the
   binary. Not a secret leak (public MIT), but dead weight.
7. **Entitlements are inert.** `Entitlements.plist` grants Calendar and
   Reminders, but without the hardened runtime or sandbox they do nothing.
   Not a bug; just not a control. If you ever notarize, keep them.

Checked and clean: no `innerHTML` or `href` with untrusted text anywhere in
`src/`; release notes render as `textContent`; `open_link` is an exact-match
allowlist; `open_event` percent-encodes the id; `create_event` caps title and
location and goes through the EventKit API, never string assembly; quick add
text is capped at 500 characters; the Google Calendar handoff is built with
`parse_with_params` from only what the user typed; every EventKit call
asserts the main thread; the dismissed set is capped and pruned; the snooze
store is capped at 20.

## Correctness

Ranked by how likely a user is to hit it.

1. **Declined meetings get the day-list countdown.** `countdownEvents`
   (`src/shared/events.ts:92`) and `dayCountdownEvents` (`:123`) filter
   all-day, ended and dismissed but not `response === "declined"`, while the
   menu bar and the Next line both skip declines. With the countdown off, a
   declined 3 pm and an accepted 4 pm show "in 15m" on the declined one.
2. **US week numbers skip a week on Monday-first months.**
   `rowUsWeekNumber` (`src/shared/calendar.ts:140`) numbers a row by its
   Sunday, which on a Monday-first row is the last day. January 2026 prints
   1, 3, 4, 5, 6, 7. Six of the row's seven days belong to week 2. The test
   at `tests/phase-6.test.ts:94` codifies the current behaviour. Fix: number
   by the row's first day; Sunday-first rows are unchanged.
3. **Settings writes fail silently.** `SettingsStore::write`
   (`settings.rs:406`) discards the `io::Result`, so a full disk or an
   unwritable Application Support folder leaves every toggle looking saved
   and the welcome screen back on next launch. Same for dismissals and
   launch-at-login. Fix: propagate as `Err(String)` so the window can say
   so.
4. **The Settings form sends every field on any change.** `patchFromForm`
   (`settings.ts:650`) ships `quickAddCalendar.value`, which is "" until the
   calendar list loads, so flipping any switch while Calendar access is
   denied wipes the saved quick-add calendar. Same for a second time zone
   not in the known list, and a half-typed meeting link. Fix: fall back to
   the saved value when a select has no matching option, and patch only the
   control that changed.
5. **A corrupt snooze store kills the reminder card.** `loadSnoozes`
   (`reminder.ts:88`) casts whatever is in localStorage; one malformed entry
   makes `takeDueSnooze` throw inside the swallowed `check()` every tick, so
   no card ever shows until storage is cleared. Fix: validate each entry.
6. **A snoozed card ignores a later dismissal** (`reminder.ts:279`). Snooze,
   then "Stop counting down" in the month: the card still returns, with the
   event as it was. Fix: re-find the occurrence and honour `dismissed`.
7. **All-day reminders spill into the next day across DST start.**
   `reminder_span` (`events.rs:240`) adds a fixed 24 h to local midnight; on
   a 23-hour day the end is 01:00 next day and the renderer buckets by
   overlap. Fix: end at the next local midnight.
8. **The month popover steals focus** (see upstream, above).
9. **`rebind_shortcut` unregisters the old chord before the new one binds**
   (`shortcuts.rs:92`); if both fail, Settings shows a chord that is not
   bound. It also ignores `shortcuts_suspended`.
10. **`request_calendar_access` chains the Reminders prompt** and can block
    three more minutes with the Dock icon showing (`lib.rs:473`).
11. **Background auto-install restarts the app** regardless of a quick add
    in progress or a reminder on screen (`updates.rs:150`).
12. **"Next:" past a week is ambiguous**: an event nine days out reads "Tue,
    11:45 AM" (`events.ts:512`).
13. Minor: sync commands fsync on the main thread (`update_settings`,
    `dismiss_upcoming_event` could be `async`); `follow_status_item` spawns
    a thread per tray repaint.

## Code quality

- **Dead code.** Nine SVGs in `icons/brands` (ChatGPT, Claude, GitHub,
  Google Calendar, Slack, X, and SVG twins of Zoom, Teams, Meet) are copied
  into the bundle and referenced by nothing; `brand-icons.ts` uses only the
  PNGs. `endOfMonth` in `calendar.ts` has no callers. `BAND_BLEED` and
  `BAND_LIFT` are both 0, so `column-bands.ts` and its tests are inert.
  `SystemRegion.firstWeekday` is sent by the host and never read. Every
  `#[cfg(not(target_os = "macos"))]` stub is unreachable since `glass.rs`
  and `Cargo.toml` need objc2 unconditionally.
- **Duplication.** `applyTheme` ×3, `requireElement` ×2, the boot chain ×3,
  the pointer-away guard ×3, the `${id}@${startAt}` occurrence key inline in
  four places, four local-midnight helpers. In Rust: `request_access` vs
  `request_reminders_access`, two spawn-and-wait blocks in `lib.rs`, the
  `NEEDS_RESET` block twice, calendar extraction three times.
- **Structure.** `startCalendar` is one 1,235-line closure and
  `startSettings` one of 870 lines, so none of it is unit-tested. Natural
  seams: day list, search panel, quick-add panel, month grid render, the
  keydown dispatcher; in Settings: update UI, shortcut recording, calendar
  sources, welcome.
- **Tests missing** for: `NewEvent::checked`, `percent_decode` and
  `query_param` on malformed input, `popover_origin` Above branch,
  `calendar_height` clamp, `reminder_span` across DST, `loadSnoozes`, the
  declined-countdown cases, `parseQuickEvent` near midnight, `isoWeekNumber`
  year boundaries (only two cases), the whole keyboard handler. `beep.rs`
  tests reimplement the formula instead of calling it.
- **tsconfig.** `types: ["node"]` applies to browser code (hence
  `window.setTimeout` workarounds); no `noUnusedLocals`,
  `noUnusedParameters`, `noImplicitOverride`.

## Dependencies and tooling

- `pnpm audit` reports 9 advisories (2 high), all through vitest 5.0.0's
  vite 8.2.2. Dev-only: the renderer is esbuild-bundled and the only
  runtime dependency is `@tauri-apps/api`. Fix: `pnpm up vitest@5.1.0`.
- `@tauri-apps/cli: ^2` is loose next to `@tauri-apps/api: ~2.11.0`. Pin
  to the same minor.
- Rust: `cargo-audit` is not installed locally and CI does not run it.
  Dependabot alerts are off on GitHub (see below), so nothing watches the
  Cargo lockfile for advisories. Add `cargo audit` to CI or turn alerts on.
- `rust-version = "1.77"` in `Cargo.toml` is unlikely to be true with
  objc2 0.6 and edition 2021 features in use; either verify or drop it.

## GitHub repository

- **Issues are disabled**, yet SECURITY.md says "ordinary bugs belong in the
  issue tracker", CONTRIBUTING.md says "issues and pull requests are
  welcome" and "open an issue before writing it", and CODE_OF_CONDUCT.md
  talks about moderating issues. Either enable issues or rewrite the three
  files.
- **Private vulnerability reporting is disabled**, yet SECURITY.md links to
  `security/advisories/new`. The link 404s for reporters. Enable it in
  Settings → Code security, or point SECURITY.md at an email.
- **Dependabot alerts are disabled** (version updates via `dependabot.yml`
  are on; security alerts are not). Enable in Settings → Code security.
- **No topics, no homepage URL.** Add topics such as `macos`, `menu-bar`,
  `calendar`, `tauri`, `rust`, `typescript`, `eventkit` so the project is
  findable; the description is fine.
- **Wiki and Projects are enabled** and unused. Turn off to avoid an empty
  Wiki tab.
- **No branch protection or ruleset on `main`.** For a solo project, at
  least "require status checks (CI) to pass" prevents a red main from a
  direct push. Optional.
- CI is green on every recent push. Actions are SHA-pinned with
  `persist-credentials: false` and read-only `GITHUB_TOKEN`. Good.
- The v0.10.0 release has all three assets (DMG, `Glance.app.tar.gz`,
  `latest.json`) and the full notes.
- CONTRIBUTING.md's scope paragraph is stale: "a month view ... can
  optionally read local macOS Calendar events" predates quick add, search,
  reminders and the rest.

## README plan

The current README is honest and reads well, but it is a feature list plus
install. A reader cannot find out what Glance needs permission for, what it
stores and where, every shortcut in one place, what to do when something
goes wrong, or how the app is put together. Proposed structure, keeping the
present voice:

1. **Header**: icon, one-line pitch, badges (CI, latest release, license,
   macOS 13+). Keep the two hero screenshots.
2. **Features**: as now, but each bullet one or two sentences shorter, and
   the second-zone, snooze and quick-add details moved under their own
   headings below.
3. **Install**: as now, plus **Update** as its own subheading, and a note on
   **Uninstall** (drag to Trash; remove
   `~/Library/Application Support/Glance` to forget settings).
4. **Permissions and privacy**: a table of Calendar, Reminders,
   Accessibility (only for global chords) and Automation (none). What each
   is used for, and what happens if it is denied. Where settings live,
   that they are owner-only, that snoozes live in the reminder window's
   local storage, and that the only outbound connections are the update
   check to GitHub and the optional Google Calendar handoff. This is the
   section a careful user looks for and it does not exist.
5. **Keyboard shortcuts**: one table. Global (⌃⌘K, join chord), popover
   (⌘N, ⌘F, ⌘,, arrows, Return, Escape), Settings, reminder card.
6. **Settings reference**: one short paragraph per pane (General,
   Appearance, Calendar, Events, About), naming each switch the way Settings
   does. Readers search README for a switch's name.
7. **Quick add syntax**: the phrases it understands ("tomorrow 1pm", "for
   30m", "at Blue Tokai", "on zoom", an email address, "on meet") in a
   table with the result of each.
8. **Troubleshooting**: first launch and Gatekeeper; Calendar access lost
   after an update (only if a release is signed differently); the join
   chord asks for Accessibility; "Checking…" hangs (the 8 s connect
   timeout); no events shown (hidden calendars, look-ahead).
9. **How it works**: two paragraphs. Tauri 2; three windows (calendar
   popover, reminder card, Settings) each with its own capability; the host
   reads EventKit through objc2 on the main thread; the renderer never sees
   a URL the host has not allowlisted; updates are signed with a key that
   cannot be rotated. Link to `docs/building.md` and `docs/release.md`.
10. **Release notes**: link to `docs/release-notes/` and the Releases page.
11. **Contributing, security, credits, license**: link CONTRIBUTING.md and
    SECURITY.md (today neither is linked from the README). Credits should
    name Calendo, Itsycal for `beep.mp3`, and the brand marks.

Also fix in `docs/building.md`: "`pnpm dev` runs the unbundled executable
with file watching for UI development" is not true. `beforeDevCommand` is a
one-shot `pnpm build` and there is no `devUrl`, so UI changes need a rerun.

## Fixed on 8 November 2026

Committed on main as 62b8fbc. Every check passes: fmt,
clippy, 84 Rust tests, typecheck, 230 TypeScript tests.

- Declines excluded from both countdown lists (`events.ts`), with a test.
- US week numbers taken from the row's first day (`calendar.ts`); the
  Monday-first test now asserts 1 to 6 with no gap.
- Snooze store validated on load through a new exported `validSnoozes`
  (`reminder.ts`), with tests. A snoozed card that was skipped from the
  month since stays away, and one still due comes back with the event as
  Calendar has it now.

  has loaded, keeps a saved second zone the list does not offer unless the
  zone select itself changed, and sends the saved meeting link unless the
  link field itself changed (`settings.ts`).

  (`tray.rs`).
- `SettingsStore::update` and `save_dismissed` return the write result;
  `update_settings` and `dismiss_upcoming_event` apply the change for this
  run, then return `Err` with the reason, and log it. The Settings window
  shows it from 7ec18d1 on, below.
- Meet requires a room code or `/lookup/`; Teams requires
  `/l/meetup-join/`, `/meet/` or `/dl/launcher/` (`events.rs`). Positives
  and negatives added to the Rust test and the shared fixture.
- vitest 5.1.0 plus vite 8.3.6 as a direct dev dependency, since the
  advisory was on a peer that an override did not reach. `pnpm audit` is
  clean. The other dev specifiers tightened to their installed versions.
- `copy-static.mjs` skips source maps and deletes stale ones when
  `GLANCE_RELEASE` is set; `release-dmg.mjs` sets it. Debug builds are
  unchanged.
- `docs/building.md`: the `pnpm dev` sentence corrected; source-map note
